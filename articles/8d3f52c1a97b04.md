# はじめに

## 前回のあらすじ

https://zenn.dev/boykush/articles/11cfc3e1abc563

mise は Dev Tools（asdf のような開発ツール管理）・Environments（direnv のような環境変数管理）・Tasks（make のようなタスクランナー）の 3 つをコンセプトに挙げる CLI ツールです。前回の記事では、brew や zshrc に分散していたマシングローバルな開発環境の設定を mise の設定ファイルへ集約し、CLI ツールのバージョン・環境変数・シェルエイリアス・自作スクリプトを静的管理するようにしました。

その中で初期セットアップスクリプトは、mise install 後に発火する postinstall hook から以下を実行する形にしていました。

- mise Registry に含まれない GUI アプリ・フォント等の brew install
- dotfiles リポジトリ内の各ツール設定ファイルを参照するシンボリックリンクの一括作成

要は mise install の1コマンドに、CLI ツールの導入からこれらのセットアップ処理までを相乗りさせ、dotfiles の整備を完結させていた形です。

## 経緯

ありがたいことに前回記事へ継続的に Like をもらっていましたが、 前回記事に関連する機能が多くリリースされたことで dotfiles の移行を進めていました。

関連する機能として、miseにDeclarative machine bootstrapと呼ばれる機能群が[v2026.6.6](https://github.com/jdx/mise/releases/tag/v2026.6.6)で追加され、[v2026.7.4](https://github.com/jdx/mise/releases/tag/v2026.7.4)（リリースタイトルは "Bootstrap goes stable"）でexperimentalを卒業しGAとなりました。

https://mise.jdx.dev/bootstrap.html

新環境のセットアップを `mise bootstrap` コマンド一発で流せるようにする機能で、前回postinstall hookでワークフロー化していたセットアップ処理を、まるごと専用の公式機能に置き換えられるようになりました。せっかくなので移行し、前回の続編として残します。

## 本記事のスコープ

miseは直近でサプライチェーン攻撃対策となるような機能（lockfileやminimum_release_age等）の拡充にも力を入れていますが、本記事では扱いません。mise本体の導入をスクリプト化する `mise generate bootstrap` も同様です。いずれも業務での実践として別記事で紹介したいと思っています。本記事は「mise導入済みのマシンで、セットアップをmise bootstrapに集約する」話に絞ります。

## 成果物

引き続き、以下のdotfilesリポジトリです

https://github.com/boykush/dotfiles

新しいマシンでのセットアップは以下の2コマンドになりました

```bash
git clone git@github.com:boykush/dotfiles.git ~/dotfiles
cd ~/dotfiles && mise bootstrap
```

前回あった `setup-mise.sh` と `mise/hooks/postinstall.sh` はリポジトリから消え、 `mise/config.toml` の宣言に置き換わっています。ついでに `.zshrc` まで消えていますが、それぞれどこへ行ったのかを本編で紹介します。
